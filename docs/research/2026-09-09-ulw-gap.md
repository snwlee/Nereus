## 4. Prime Agent — 원문 전수 요약

- 제목: `Prime Agent: A self-improving RLM agent`, 2026-08-05, Prime Intellect. 오픈소스 `PrimeIntellect-ai/prime-agent`, 기반 `pi`. Technical report 예고.
- 테제: 고정 tool-schema+compaction+정적 sub-agent는 구세대. RLM+Continual Harness로 외삽.

### 4.1 아키텍처·오케스트레이션·세션·학습·자율

- 유일 tool=지속 IPython kernel. `await rlm("...")` 핸들 즉시반환+`agent_message.send` 비동기 reply+mid-flight steer.
- 데몬이 live session을 socket 소유. worker crash시 JSONL+snapshot 복구. Agents View(Running-Idle-Inactive, 30분 unload, space steering/queue). A2A nuclear family 제한. Persistent sub-agent(`rlm.list_subagents()`+follow_up, compaction/kernel restart 생존).
- history=append-only JSONL. branching/fork/clone은 leaf pointer. `/tree` 복구. compaction 임계/`compact.run()` 수동+`compact.status()`+GC sub-agent.
- Harness H=(ρ,G,K,M) 동일 CRUD+`/refine` 2-phase(planning 백그라운드+apply 턴경계, base immutable, ID rollback, trigger+outcome 기록).
- Autonomous: goal+budget+heartbeat(cron)+continuation+`--autonomous-gate "npm run check"`(실패 bounded반환, 무변경 skip)+turns/tokens/timeout 바운드.

### 4.2 수치(글 기재 그대로)

- ARC-AGI-3(Opus5+Prime): 95.5% Best@1(human 95.4% 초과), Best@3 99.97%(183/183). 토큰↓ 이유는 함수실행.
- Long-context 9종(GLM-5.2/Opus5/GPT-5.6 Sol × Prime vs native): 표는 원문 §2 참조. EmulatorBench Prime 우위, OOLONG yahoo는 native 우위 케이스도 있음.
- PMPP-Hard/Factorio(100K+ 수시간, reward hacking: RCON 자원spawn을 refinement가 효율화)/MazeBench는 그래프 위주.
- 입장: 어떤 모델도 harness 중심 학습된 적 없음. model-harness co-learning이 지배 패러다임.

### 4.3 ULW 번역 5개 [글 외부]

1. programmatic fan-out(중): REPL+handle+on_reply 큐.
2. daemon+CLI(중-하, 1순위): TUI 없이 list/attach/steer/queue+JSONL+LRU.
3. harness CRUD+/refine(중): 단일 store+최소편집+불변코어+롤백+승인게이트+금지패턴.
4. autonomous gate(하, 가장쌈): `--gate`+skip. 야간벤치 직행.
5. kernel-aware compaction(중): compact 함수노출+“읽기 대신 실행” 린트.

### 4.4 소스 실검증 (2026-09-10, `PrimeIntellect-ai/prime-agent@81cd539`)

§4.1~4.3 은 **블로그 텍스트만** 근거였다. 저장소를 받아 코드로 확인한 결과 대체로 맞았지만
두 곳이 틀렸고, 블로그에 없던 사실이 하나 나왔다. 구조는 TS 모노레포
(`packages/{agent,ai,coding-agent,tui}`) + 파이썬 런타임(`prime-agent-runtime/src/rlm/`).

**확인됨**

- `H=(ρ,G,K,M)` 는 실제 타입이다 — `refinement.ts:23`
  `RefinementKind = "prompt" | "memory" | "skill" | "subagent"`.
  저장은 `harness_state.json`(`HarnessState { schema, entries, refinements }`).
- 롤백 실재. 단 스냅샷 복원이 아니라 **역편집 생성**이다(`rollbackProposal()`, `:852`) —
  `appliedEdits` 를 역순으로 돌며 각 편집의 `before`/`after` 로 반대 edit 을 만든다.
- 근거 기록 실재. `HarnessRefinementEvent { id, trigger, changes, evidence, outcome, created_at }`.
- plan/apply 분리 실재. 다만 이유는 "턴 경계"가 아니라 **동시성**이다(`:905` 주석) — LLM 호출이
  수 초 걸리는 동안 커널이나 **다른 세션**이 공유 `harness_state.json` 을 쓸 수 있어, apply 직전
  재읽기 + `baselineState` 로 충돌 편집을 거부한다.

**틀렸던 것**

1. "시스템 프롬프트를 재조립한다" → **아니다.** 하네스 상태는 시스템 프롬프트에 들어가지 않는다.
   `system-prompt.ts` 의 harness 언급은 doctrine 1줄뿐이고, 실제 전달은 별도 대화 메시지
   (`messages.ts:118`, `<harness_state>` digest, `display:false`)다. 즉 base 프롬프트 불변은
   프롬프트 문구(`refinement.ts:131`)만이 아니라 **구조로도** 강제된다.
2. "`/refine` 은 사용자·모델이 부른다" → 주 경로가 빠졌다. `RefinementSource = "auto"|"user"|"self"`
   (`messages.ts:100`)이고, **`auto` 가 기본 25 어시스턴트 턴마다 자동 발화**한다
   (`settings-manager.ts:26,912`). compaction 시점에도 발화. 그냥 돌지 않고 **두 번째 LLM 호출이
   게이트**를 본다(`AUTO_REFINE_REVIEW_SYSTEM_PROMPT` → `{shouldRefine, rationale, instructions}`).
   비용: 25턴마다 LLM 2회 추가.

**블로그에 없던 것**

- 모델은 `/refine` 없이도 REPL 에서 하네스를 직접 CRUD 한다(`prompts/rlm.ts:47`):
  `rlm.harness.create_memory(...)`, `update_skill(...)`, `create_subagent(...)`,
  `record_refinement(...)`, `overview()`.
- **스코프 이원화**: 기본은 **세션 로컬**, `global_=True` 가 옵트인. 로컬 refinement 중 글로벌
  항목은 읽기 전용이고 update/delete 를 금지한다(프롬프트 정책 + 스토어 분리).

### 4.5 판정 — 채택/비채택 (2026-09-10)

**Prime 아키텍처 자체는 비채택.** 테제가 정면 충돌한다. Prime 은 에이전트가 규칙(ρ,G,K,M)을
고칠 수 있게 하는 게 상품이고, Nereus 는 못 고치게 하는 게 상품이다(PreToolUse 규칙 편집 차단,
`/nereus:learn` 사람 승인). 또 Prime 수치의 전제인 model-harness co-learning 은 범위 밖이다(§7).

**채택 완료**: autonomous gate → `runLoop` 배선(아래 §4.6). Prime 항목은 이걸로 닫는다.

**기록만 남기는 채택 후보 2개** — 자기진화 없이도 가져올 수 있고, 지금 Nereus 에 없다:

| 후보 | Prime 근거 | Nereus 현황 | 값 |
|---|---|---|---|
| 학습 스코프 로컬/글로벌 분리 + 글로벌 옵트인 | `HarnessScope = "local"｜"global"`, 기본 local | `/nereus:learn` 승인 규칙이 전역에만 꽂힌다. "이 프로젝트에서만"을 표현할 수 없다 | 중 |
| 승인된 규칙의 역편집 롤백 | `rollbackProposal()` before/after 역편집 | 승인이 나빴을 때 되돌릴 경로가 없다 | 중 |

둘 다 P2. 지금 하지 않는다 — 남은 우선순위는 실전 검증(`/nereus:intake` 첫 사이클)이다.

### 4.6 배선 결과 (2026-09-10)

`autonomousGate()` 는 순수 함수·테스트·SKILL.md 문서까지 있었으나 **호출처가 0건**이었다.
SKILL.md 가 "유일한 진실원천"이라 써둔 상태로 실제로는 아무것도 게이트하지 않았다. 배선하며
드러난 실제 결함:

1. `evaluate()`(=`ooo qa`)는 **태스크가 전부 끝났을 때만** 돌았다. 그 전 반복은 검증 없이 커밋.
2. 진행 판정이 **서브세션 자기신고**(체크박스)였다.
3. 기존 `stuck` 카운터는 "같은 태스크" 키로 세서, 체크박스가 넘어가면 키가 바뀌어 리셋된다 —
   게이트가 계속 깨져도 `max` 까지 걸어간다. 그래서 **연속 게이트 실패는 별도 카운터**가 필요했다.

배선 내용은 `plugins/nereus/skills/loop/SKILL.md` 의 "자율 게이트" 절이 정본. 요약: 커밋 직전
게이트, 무변경 skip, 실패해도 커밋은 하되 메시지에 남기고 **진행으로 세지 않음**, 연속 3회면
`gate_blocked`, `--timeout` 소진이면 `budget_exhausted`. 판정 순서는 기존 `stuck` 이 우선(기존
동작 불변). **남은 한계**: wave 병렬에서는 워크트리가 먼저 커밋·병합된 뒤 게이트가 돌아 사후
검증이다. 막으려면 게이트를 `runWave` 안 커밋 앞으로 내려야 한다.
