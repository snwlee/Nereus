# nereus-ads

AdMob 운영 하네스. `nereus` 코어의 워크플로(intake → spec → build → review → finish) 위에서
**광고 도메인만** 담당한다. 게임·비게임을 가리지 않는다 — 배경화면 앱도 유틸도 같은 정지 사유를 갖는다.

## 왜 별도 플러그인인가

광고는 **가장 위험하고 가장 조용한 코드**다.

- 정책을 어기면 **계정이 정지**된다. 그 앱 하나가 아니라 계정에 달린 앱 전부가 멈춘다.
- 수익을 흘려도 **아무 에러도 안 난다**. 릴리스에 남은 데모 단위, 동의 대기로 건너뛴 뒤
  재시도가 안 걸린 로드, 빈 타게팅 요청 — 전부 빌드 초록이고 광고도 잘 보인다.

둘 다 사람 주의력으로는 안 잡힌다. 그래서 검사기로 옮긴다.

게임 전용이 아니므로 `nereus-game` 에 두지 않는다. 코어에 두지도 않는다 —
코어 라우터는 한 프롬프트당 스킬 2개(`MAX_HITS`)만 지목하고, 광고 라우트를 코어에 섞으면
웹·앱 작업 프롬프트에서 자리를 뺏는다.

## 출처

`WallpaperEngineApp` 에서 채굴했다(광고 소스 4,985줄 · 계약 테스트 22개 · 수익 보고서, 2026-09-13).
그 저장소가 ToonTone 광고 정책의 도너다 — **이미 대가를 치른 지식**이다.
실측 수익 수치(eCPM·RPM·show rate 실제값)와 퍼블리셔 ID 는 **가져오지 않았다**.
계정·시점 종속이라 빨리 낡고, 조용히 낡은 수치가 틀린 확신을 만든다. 방법론만 옮겼다.

## 세 축

| 축 | 스킬 | 성격 | 검사기 |
|---|---|---|---|
| 정책 | [`adpolicy`](skills/adpolicy/SKILL.md) | **게이트** — 어기면 정지 | `lib/ad-policy-check.mjs` |
| 배치 | [`adplacement`](skills/adplacement/SKILL.md) | 설계 방법론 — 정지 사유가 아니다 | 없음 |
| 수익 | [`adrevenue`](skills/adrevenue/SKILL.md) | **조언자** — 사업 판단이다 | `lib/ad-funnel.mjs` |

에이전트는 [`ads-engineer`](agents/ads-engineer.md) 하나다. 구현 절차(TDD·게이트)는
`nereus:build` 의 것을 그대로 쓴다 — 여기서 다시 정의하지 않는다.

## 검사기가 둘인 이유

`Ruling: 게이트와 조언자는 파일을 나눈다 — 정지 위험과 수익 기회는 무게가 다르다.`

| | `ad-policy-check.mjs` | `ad-funnel.mjs` |
|---|---|---|
| 낸다 | `violations` | `levers` · `unanswerable` |
| 통과·차단을 판정하나 | **한다** | 하지 않는다 |
| 기준이 없으면 | 축을 검사하지 않는다 | 병목을 판정하지 않고 그 사실을 싣는다 |

한 파일에서 같이 내면 "계정 정지 위험"이 "배너 단가 좀 낮음" 옆에 나란히 붙어 진짜가 묻힌다.

```bash
echo '{"build":{"debug":false},"units":[…]}' | node "${CLAUDE_PLUGIN_ROOT}/lib/ad-policy-check.mjs"
echo '{"formats":[…],"targets":{…}}'         | node "${CLAUDE_PLUGIN_ROOT}/lib/ad-funnel.mjs"
```

두 검사기 모두 **주지 않은 축은 검사하지 않는다.** 모르는 것과 통과한 것을 같게 보고하면
검사되지 않은 것이 통과로 읽힌다.

## 정책 데이터

`ads-policy.json` 이 포맷 목록 · 플랫폼별 데모 단위 표 · 중단형 포맷을 갖는다.
전부 **구글이 정하고 구글이 바꾸는 값**이라 코드에 박지 않고 `source` · `checkedAt` 과 함께 둔다.
경계 선언에는 `why` 가 같이 붙는다 — 이유 없는 경계가 가장 먼저 지워진다.

## 경계 — 여기서 하지 않는 것

- **원격 설정 키 분류**는 `nereus-game:liveops` 가 한다. 광고 키도 원격 설정 키의 한 종류일 뿐이고,
  분류 규칙은 이벤트·경제 키와 같다.
- **확률형 아이템 규정**은 `nereus-game:compliance` 가 한다.
- **개인화 여부 판정**은 하지 않는다. UMP 동의와 SDK(TCF 문자열)가 정한다 —
  두 곳이 같은 것을 정하면 갈리는 순간 어느 쪽이 진실인지 알 수 없다.
- **구현 절차**는 `nereus:build` 가 갖는다.

## 다른 플러그인과의 관계

**이 플러그인은 다른 플러그인이나 코어의 내부 모듈을 import 하지 않는다.**
`lib/cli-input.mjs` 도 이 플러그인의 것이다. 플러그인이 서로의 내부에 붙으면
설치 조합에 따라 조용히 깨진다.

에이전트·스킬 이름은 `nereus` · `nereus-game` 과 겹치지 않는다. 겹치면 한쪽이 다른 쪽을 가린다
(2026-09-13 에 `writer` 로 실제로 겪었다). `/nereus:doctor` 가 이것을 검사한다.
