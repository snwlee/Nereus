# 게으름 사다리 (laziness ladder)

`nereus:build` 의 **GREEN 단계** 규율. 무엇을 만들지를 정한다 — 어떻게 검증할지는 정하지 않는다.

## 출처

[DietrichGebert/ponytail](https://github.com/DietrichGebert/ponytail) (**MIT**) 의 "the ladder" 를
가져와 Nereus 에 맞게 줄였다. 상류 측정(에이전틱, Haiku 4.5, 무스킬 대비):
LOC 46% · 토큰 78% · 비용 80% · 시간 73%.

상류 README 가 스스로 밝히듯 화제가 된 "코드 80-94% 감소"는 **대화형 베이스라인 아티팩트가
섞인 수치**이고, 방어 가능한 것은 위 에이전틱 수치다. 그 구분을 여기 남긴다.

## 사다리 — 버티는 첫 단에서 멈춘다

1. **애초에 있어야 하나?** 짐작으로 만드는 것은 만들지 않는다. 건너뛴 이유를 한 줄로 남긴다. (YAGNI)
2. **이 저장소에 이미 있나?** 헬퍼·유틸·타입·패턴이 몇 파일 건너 이미 산다. 쓰기 전에 본다.
   코드 재작성은 가장 흔한 낭비다. **CodeGraph 가 있으면 grep 보다 먼저 `codegraph_explore` 로 본다.**
3. **표준 라이브러리가 하나?** 쓴다.
4. **플랫폼 기본 기능이 덮나?** 라이브러리보다 네이티브, JS 보다 CSS, 앱 코드보다 DB 제약.
5. **이미 설치된 의존성이 푸나?** 쓴다. 몇 줄로 되는 일에 **새 의존성을 더하지 않는다.**
6. **한 줄로 되나?** 한 줄로 한다.
7. **그때서야** 동작하는 최소 코드.

두 단이 다 되면 **위쪽(더 게으른) 단**을 택하고 넘어간다.

## 사다리는 해답을 줄이지, 읽기를 줄이지 않는다

**문제를 이해하는 데는 게으르지 않는다.** 변경이 닿는 파일과 실제 흐름을 끝까지 훑은 **뒤에**
단을 고른다. 이해를 건너뛰고 작은 diff 를 내는 것은 효율로 위장한 **자신 있는 오답**이다.

버그는 **증상이 아니라 근본 원인**에서 고친다. 공유 함수에 가드 하나가 호출부마다 가드를
넣는 것보다 작은 diff 이고, 티켓이 지목한 경로만 고치면 나머지 호출부는 **그대로 깨져 있다**.
이 판단의 절차는 `nereus:debug` 가 갖는다 — 여기서 다시 정의하지 않는다.

## 줄이면 안 되는 것

다음은 어떤 단에서도 깎지 않는다:

- **입력 검증** — 신뢰 경계에서는 언제나.
- **에러 처리** — 데이터 손실을 막는 것.
- **보안** — 인증·권한·비밀값.
- **접근성** — 기본은 협상 대상이 아니다.
- 사용자가 **명시적으로 요청한 것**. 전체 버전을 원하면 만든다. 다시 따지지 않는다.

의도적으로 한계를 안고 단순화했다면 `ponytail:` 주석으로 **한계와 올라갈 길**을 적는다
(`// ponytail: 전역 락, 처리량이 문제되면 계정별 락으로`).

## 가져오지 않은 것

상류의 **테스트 최소주의를 가져오지 않았다.** ponytail 은 "프레임워크 없이 작은 검사 하나,
사소한 한 줄짜리는 테스트 불필요"라고 한다. Nereus 는 **TDD 를 훅으로 강제**하고 커버리지
기준을 갖는다(`nereus:build` 2절, `rules/common/testing.md`). 두 규칙이 같이 있으면
**이중 게이트**가 되고, 느슨한 쪽이 조용히 이긴다.

**충돌 시 Nereus 의 TDD 게이트가 이긴다.** 사다리는 *무엇을 만들지*만 정한다.

상류의 말투 규칙(출력 길이·설명 금지)도 가져오지 않았다. 그것은 하네스가 아니라 취향이고,
`nereus:common` 이 이미 자기 출력 계약을 갖는다.
