# level

nereus:common 규칙을 따른다. 담당 에이전트: level-designer.
**엔진과 무관하다** — 레벨의 구조와 곡선은 로블록스든 Unity든 같다.

## 1. 루프를 구조로 옮긴다

장르 프로파일의 `loop` 가 레벨의 뼈대다.

```js
import { loadProfile } from "../../lib/profiles.mjs";
loadProfile("sim-tycoon").loop;       // 수집 → 판매 → 재투자 → 확장
loadProfile("obby-platformer").loop;  // 도전 → 실패 → 재시도 → 통과
```

레벨 하나는 **루프를 최소 한 바퀴 돌 수 있어야 한다.** 한 바퀴가 안 도는 레벨은 레벨이 아니라 장식이다.
루프 한 바퀴에 걸리는 시간을 먼저 정하고(타이쿤 30~90초, 오비 10~30초가 출발점), 그 배수로 레벨을 잡는다.

## 2. 난이도 곡선

톱니 모양으로 만든다 — 올리고, 잠깐 내리고, 더 올린다. 단조 증가는 지치고, 평탄은 지루하다.

| 요소 | 질문 |
|---|---|
| 도입 | 새 요소를 **안전한 곳에서** 먼저 보여줬는가. 위험과 학습을 같은 순간에 주지 않는다 |
| 반복 | 배운 것을 한 번 더 쓰게 했는가. 한 번 쓰고 버리는 요소는 기억되지 않는다 |
| 결합 | 앞의 두 요소를 합쳐 쓰는 지점이 있는가. 여기가 실제 난이도다 |
| 회복 | 실패 후 재시작 지점이 가까운가. 오비에서 이 거리가 곧 이탈률이다 |

체크포인트 간격은 **평균 재시도 횟수**로 역산한다. 한 구간을 5회 넘게 재시도하게 되면 구간을 쪼갠다.

## 3. 밸런싱과 이어 붙인다

레벨 비용 구조를 `nereus-game:balance` 의 `stages` 로 옮겨 시뮬레이터에 넣는다.

- 타이쿤: `bottlenecks` 가 비어야 한다. 못 깨는 단계가 곧 벽이다.
- 오비: `cliffs` 가 이탈 구간이다. 절벽 앞에 중간 구간을 끼워 넣는다.

프로파일의 `balance.failureMode` 가 어느 쪽을 먼저 볼지 정한다.

## 4. 절차적 생성을 쓸 때

**결정론적인 것만 쓴다.** WaveFunctionCollapse·MarkovJunior 는 시드가 같으면 결과가 같아
레벨을 테스트할 수 있다 — 생성물 자체를 회귀 테스트 대상으로 둘 수 있다는 뜻이다.

- 시드를 레벨 데이터에 저장한다. 저장하지 않으면 재현이 불가능하고 버그 신고가 무의미해진다.
- 생성 결과를 **검증 규칙**과 짝지운다(도달 가능한가, 막힌 구간이 없는가, 최소 경로 길이가 범위 안인가).
  검증 없는 생성은 무작위 쓰레기를 대량 생산한다.
- LLM 으로 레벨을 생성하지 않는다. 재현이 안 되고 검증도 안 된다.

## 5. 검증

- 모든 목표 지점에 도달 가능한가 (경로 탐색으로 기계 검증)
- 의도하지 않은 지름길이 있는가 — 루프를 건너뛰면 경제가 무너진다
- 각 구간의 예상 소요가 목표 범위 안인가

## 6. 퍼즐 판

판 퍼즐은 생성한 판마다 기계 검증을 붙인다. 플레이로는 늦게 드러나는 두 가지다.

```bash
echo '{"kind":"match3","board":[[1,1,2],[2,3,1],[3,2,3]]}' | node plugins/nereus-game/lib/puzzle-board.mjs
echo '{"kind":"sliding","tiles":[1,2,3,4,5,6,7,8,0],"width":3}' | node plugins/nereus-game/lib/puzzle-board.mjs
```

| 위반 | 뜻 | 대응 |
|---|---|---|
| `initial-match` | 시작부터 3연속 | 공짜 연쇄가 터진다. 채울 때 줄을 완성하는 색을 거부한다 |
| `deadlock` | 어떤 인접 교환도 매치를 못 만든다 | 소프트락. 개수를 유지한 채 섞되 섞은 판도 매치가 없어야 하고, 시도 상한 뒤 새 판 |
| `unsolvable-parity` | 슬라이딩 판이 패리티상 풀 수 없음 | 무작위 섞기는 절반이 이렇다. 숫자 타일 두 개를 바꾸면 뒤집힌다 — 또는 정답에서 역방향 이동으로 섞는다 |

판 규칙은 화면이 아니라 데이터에 둔다 — 애니메이션은 해소 결과를 재생할 뿐이고, 해소가 끝날 때까지 입력을 잠근다.
되돌리기는 판·점수·남은 수·**난수 상태**까지 전부 복원한다(난수를 빼면 되돌리기로 리롤이 된다).
출처: awesome-gamedev-agent-skills `genres/puzzle` (Apache-2.0).

## 7. 동적 난이도와 난이도 손잡이

### 손잡이는 레벨 데이터에 둔다

이동 수, 조각·색 생성 가중치, 시간 제한, 도움 규칙 on/off, 마지막 수 보너스는 **레벨 파일의 필드**다.
코드에 있으면 레벨 하나를 고치려고 다시 빌드해야 하고, 시뮬레이터로 레벨별 승률을 비교할 수 없다.

- [ ] 레벨 스키마에 위 손잡이가 필드로 있다. 게임 로직에 난이도 매직넘버가 없다(grep)
- [ ] 필드만 다른 두 레벨을 시드 고정 시뮬레이션에 넣으면 승률이 다르게 나온다

### 동적 난이도는 "수마다 목표 진척 범위"로 만든다

레벨마다 수(또는 시간)별 기대 진척의 하한·상한을 데이터로 둔다(`progressBand[move] = {lower, upper}`).
하한 아래면 돕고, 상한 위면 조인다. **입력은 플레이 상태뿐이다** — 진척, 남은 수, 연속 실패.

- [ ] 레벨 데이터에 진척 범위 표가 있다
- [ ] 시드 고정 시뮬레이션에서 개입 전후 승률이 목표 범위 안으로 들어온다
- [ ] 난이도 함수의 인자에 결제 여부·광고 가치·기기 모델·국가가 없다

### 게이트 — 난이도·점수를 돈 신호에 묶지 않는다

광고 가치·결제 여부·기기 모델·국가가 난이도·승패·점수·드롭 계산에 들어가면, 같은 실력이
사람마다 다른 결과를 받는다. 몰래 점수를 더하거나 "이번 판은 지게" 만드는 규칙도 같다.
**사람의 주의력으로는 안 지켜진다** — 수익 팀의 신호 하나를 넘겨받는 import 한 줄이면 무너진다.
그래서 `craft` 의 계층 경계 검사기로 기계 판정한다.

```bash
echo '{"declarations":[{"layer":"lib/game/difficulty","forbid":["/ads/","/iap/","/monetization/","isPayer","adValue","deviceModel","countryCode"],"why":"난이도·점수의 입력은 플레이 상태뿐이다. 돈 신호가 들어오면 같은 실력이 사람마다 다른 결과를 받는다."}],"sources":[...]}' \
  | node "${CLAUDE_PLUGIN_ROOT}/lib/purity-check.mjs"
```

`layer`·`forbid` 는 프로젝트의 경로와 필드 이름으로 바꾼다. 점수·드롭 모듈이 따로 있으면 선언을 하나씩 더 둔다.
`layer-import` 위반이 0 이어야 통과다. 문자열 근사라 이름을 바꿔 들여오면 못 잡는다 —
그래서 결정론 테스트를 짝으로 둔다: **같은 시드·같은 입력이면 사용자 세그먼트와 상관없이 같은 판이 나온다.**

## 하지 말 것

- 난이도를 "느낌"으로 조정하지 않는다. 재시도 횟수와 구간 이탈률로 본다.
- 난이도·점수·드롭을 광고 가치·결제 여부·기기·국가에 묶지 않는다. 입력은 플레이 상태뿐이다.
- 난이도 손잡이를 코드 상수로 두지 않는다. 레벨 데이터의 필드로 둔다.
- 새 요소를 위험한 곳에서 처음 보여주지 않는다.
- 시드 없는 절차적 생성을 쓰지 않는다.
