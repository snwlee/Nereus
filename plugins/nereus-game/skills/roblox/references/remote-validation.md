`SKILL.md §3` 리뷰 1~3번(클라이언트 신뢰·서버 권위·레이트 리밋)의 근거다.

## 1. 보내는 것은 의도이지 결과가 아니다

Remote 는 "업그레이드 `Income` 을 사고 싶다"를 싣는다. 가격·수량·피해량·좌표·소유 판정처럼
**서버가 계산할 수 있는 값은 받지 않는다.** 받아서 쓰면 CRITICAL 이다.

## 2. 전송 고르기

| 종류 | 쓰는 곳 | 쓰지 않는 곳 |
|---|---|---|
| `RemoteEvent` | 순서·전달이 보장돼야 하는 요청·사실 | 새 값이 옛 값을 대체하는 연속 표본 |
| `UnreliableRemoteEvent` | 잃어도 되는 연속·장식 상태 | 구매·피해·인벤토리·한 번뿐인 상태 전이 |
| `RemoteFunction` | 즉답이 꼭 필요한 짧은 클라→서버 질의 | **서버→클라 호출**(클라가 안 돌려주면 서버가 멈춘다) |

- 신뢰 불가 전송은 크기 상한을 넘으면 **조용히 버려진다.** 표본은 하나만으로 완결되게, 순번을 넣어 옛 것을 무시하게 만든다.
- 클라→서버 호출에는 클라이언트당 상한이 있다. 정상 플레이어가 매 프레임 신뢰 전송을 쏘면 공격자보다 먼저 거기 걸린다.

## 3. 검증 순서 — 싼 것부터 거절한다

1. 레이트 예산(토큰 버킷 — 비용은 서버 영향에 비례)
2. 인자 개수·타입
3. 숫자 유한성(`v == v` 로 NaN, `math.huge` 비교)·범위
4. 문자열 길이·허용 목록, 테이블 깊이·키 개수·정확한 키 집합
5. 인스턴스 클래스·조상·태그·소유자
6. 서버가 아는 플레이어 상태 — 생존·**현재** 캐릭터·쿨다운·권한·팀
7. 거리·겹침·시야 — 서버가 관측한 상태로
8. 그다음에야 비싼 일과 상태 변경

임의 콜백 이름·모듈/에셋 id·DataModel 경로를 받아 넓게 바꾸는 Remote 를 만들지 않는다.
Remote 이름을 숨기거나 바꾸는 것은 보안 경계가 아니다.

## 4. 양보 경합 — 쿨다운 하나로 두 번 통과한다

같은 플레이어의 메시지는 순서대로 **시작**하지만, 핸들러가 양보(`task.wait`·DataStore 호출·`WaitForChild`)하면
다음 메시지가 그 사이에 시작한다. 검사 → 양보 → 적용 코드는 두 요청을 다 승인한다.
**첫 양보 전에** 쿨다운을 점유하거나 진행 중 표시를 한다. 경제에서는 잔액 확인과 차감 사이에 양보가 없어야 한다.

## 5. 복제·수명

- 개인 정보·한 명의 UI 신호는 `FireClient`. 모두가 알아야 하는 사실만 방송한다. 근처 효과는 서버가 수신자를 고른다.
- 요청은 죽음·리스폰·스트리밍 변화·퇴장 뒤에 도착할 수 있다. 처리 시점에 현재 캐릭터를 다시 찾고, 퇴장 때 플레이어별 리미터 데이터를 지운다.
- 네트워크 소유권은 반응성을 주지만 그 클라가 물리를 움직이게 한다. **소유권은 권한이 아니다** — 결과는 서버가 검증한다.
- 예측은 되돌릴 수 있는 표현에만. 피해·화폐·인벤토리·진행도를 예측이 주지 않는다.
- `Workspace.AuthorityMode` 를 다른 작업의 부수효과로 바꾸지 않는다. 프로젝트 전체 이전이라 선택지로 보고만 한다.

## 6. 남용 매트릭스 — Server & Clients 로 확인한다

가능하면 클라 둘 이상, 서버·클라 Output 을 따로 본다.

| 경우 | 기대 |
|---|---|
| 정상 요청 | 서버 변경 정확히 1회, 맞는 수신자 갱신 |
| 잘못된 타입·NaN·거대값 | 오류·비싼 작업 없이 거절 |
| 모르는·조상이 틀린 인스턴스 | 거절, 무관한 인스턴스 그대로 |
| 폭주·지속 스팸 | 리미터가 거절, 서버 응답 유지, 로그 상한 |
| 핸들러 양보 중 같은 플레이어 2요청 | 변경 최대 1회 |
| 사거리 밖·권한 없음·쿨다운 | 상태 불변 |
| 요청 중 사망·리스폰 | 낡은 요청 거절, 새 캐릭터 정상 |
| 처리 중 퇴장 | 남은 테이블 항목·콜백 오류 없음 |
| 두 플레이어 동시 | 예산·상태가 플레이어별, 교차 누출 없음 |
| 대상 지정 메시지 / 방송 | 대상만 / 전원이 정확히 1회 |

타이밍 민감 경우는 지연·손실을 더해 다시 돈다(Studio Network Simulator). 기형 호출을 넣으려고 프로덕션 검증을 약하게 하지 않는다 —
같은 순수 검증 함수를 부르는 Studio 전용 하네스를 쓰고 테스트 뒤 지운다. 못 돌린 경우는 명시적으로 적는다.
검증 함수를 DataModel 밖 순수 모듈로 두면 1단(lune)에서 대부분이 잡힌다(`SKILL.md §2`).
