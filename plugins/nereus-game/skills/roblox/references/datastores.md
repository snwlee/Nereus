# DataStore — 진행도를 잃지 않는 판단

> 출처: awesome-gamedev-agent-skills (@ 19d93f9) `skills/other-engines/roblox-datastores` — Copyright 2026 Abhishek Barali and contributors, Apache-2.0
> (`plugins/nereus-game/LICENSES/Apache-2.0.txt`). 판단 지식만 골라 한국어로 다시 썼다. API 시그니처·수치 한도는 바뀌므로
> 여기 적지 않는다 — 내장 Studio MCP 의 API 문서와 create.roblox.com 이 진실이다.

`SKILL.md §3` 리뷰 5번("DataStore 쓰기 — 실패·재시도·세션 잠금")의 근거다. 진행도 소실은 되돌릴 수 없다.

## 1. 로드 실패는 신규 플레이어가 아니다

- 모든 비동기 호출은 `pcall` 로 감싼다. 감싸지 않은 실패는 스레드를 죽이고 그 뒤 저장 경로가 사라진다.
- **로드가 실패하면 그 세션은 저장하지 않는다.** 기본값으로 시작한 세션이 저장되는 순간 진짜 데이터가 덮인다.
- 저장 조건은 "로드가 실패하지 않았다"가 아니라 **"로드가 성공했다"** 다. `GetAsync` 가 아직 끝나기 전에
  플레이어가 나가면 실패 표시도 성공 표시도 없다 — 앞의 조건은 그 세션을 저장해 버린다.

## 2. 읽고-고치고-쓰기는 `UpdateAsync`

- `SetAsync` 는 맹목 덮어쓰기다. 두 서버가 같은 키를 쓰면 한쪽이 사라진다.
- `UpdateAsync` 콜백은 **양보(yield)하지 않고 부수효과가 없어야 한다.** 다른 서버가 먼저 쓰면 콜백이 다시 돈다 —
  콜백 안에서 아이템 지급·Remote 발사·카운터 증가를 하면 두 번 일어난다. 값을 미리 계산해 돌려주기만 하고, 행동은 호출이 끝난 뒤에 한다.
- 메타데이터·UserId 를 쓰는 키는 **매 쓰기마다 다시 넘긴다.** 안 넘기면 지워진다.

## 3. 세션 잠금

순간이동·빠른 재접속으로 한 플레이어가 잠깐 두 서버에 있을 수 있다. 둘 다 로드하고 나중에 둘 다 저장하면 쓰기가 사라진다.

1. 로드 때 `UpdateAsync` 로 키에 이 서버의 `JobId` 와 시각을 찍는다 — 잠금이 없거나 **오래된(종료 예산보다 긴)** 경우에만.
2. 살아 있는 서버가 잡고 있으면 몇 번 재시도한 뒤 내보내거나 읽기 전용으로 연다.
3. 저장·퇴장 때 같은 `UpdateAsync` 안에서 잠금을 푼다.

직접 짜면 순간이동과 빠른 재접속 경우를 반드시 테스트한다. 검증된 오픈소스 세션 라이브러리를 쓰는 편이 대개 낫다.

## 4. 재시도는 멱등한 것만

- 백오프 재시도는 **다시 해도 결과가 같은** 연산에만 건다. 전체 상태를 쓰는 `UpdateAsync` 는 안전하고, `IncrementAsync` 는 두 번 더해질 수 있다.
- **실패 응답은 쓰기가 안 됐다는 증거가 아니다.** 응답만 놓쳤을 수 있다. 결과가 중요하면 캐시를 끈 읽기로 확인한 뒤 재시도한다.
- 읽기는 몇 초간 캐시된다. 쓰기 직후 확인 읽기는 캐시를 끈다.

## 5. 저장 시점과 한도

- 퇴장·서버 종료(`BindToClose`)·주기 타이머(60~120초)에 저장한다. **값이 바뀔 때마다 저장하지 않는다** — 한도에 걸려 요청이 큐에 쌓이다 버려진다.
- 서버 종료 콜백에는 시간 예산이 있다. 남은 플레이어를 병렬로 저장하고 다 끝날 때까지 기다린다.
- 직렬화 가능한 값만 저장한다(숫자·문자열·불리언·문자열/숫자 키 테이블). 위치·인스턴스는 평범한 테이블로 바꾼다.
- 저장하는 테이블에 `schema` 버전을 둔다. 마이그레이션 판단은 `nereus-game:save` 의 `save-check.mjs` 와 같다.
- 정확한 한도 수치는 공식 "error codes and limits" 문서를 본다. 바뀐다.

## 6. 삭제 요청(RTBF)

사용자 데이터 삭제 요청에 응할 책임이 있다. 플레이어가 닿는 **모든 스토어·키 목록**을 유지해야 삭제가 완전하다.
Open Cloud 로 게임 밖에서 지울 수 있고, 그 API 키는 비밀이다 — 게임·클라이언트 코드에 넣지 않는다.

## 테스트

Studio 에서는 *Studio Access to API Services* 를 켜야 하고 **라이브 데이터를 친다** — 별도 테스트 플레이스를 쓴다.
접속 → 값 변경 → 재접속으로 유지되는지, 로드 중 퇴장·두 서버 동시 접속을 확인한다.
