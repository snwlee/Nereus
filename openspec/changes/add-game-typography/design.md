# design — add-game-typography

## 결정 1: 새 스킬이 아니라 기존 도메인 확장이다

폰트의 축은 넷이고 각각 이미 주인이 있다:

| 축 | 주인 |
|---|---|
| 라이선스(게임 임베딩 허용) | `asset` — 생성물 라이선스를 이미 본다 |
| 글리프 커버리지 · 폭 | `localization` — 로케일이 여기 있다 |
| 가독성(최소 크기·외곽선) | `gameux` — 읽히는가가 이 스킬의 축이다 |
| 파일 크기 | `asset` 의 예산 개념 |

검사기는 `lib/font-check.mjs` 하나로 두고 `localization` 이 주 소비자가 된다.

`Ruling: 폰트는 새 스킬이 아니라 기존 도메인의 확장이다 — 축이 넷이고 전부 주인이 있다.`

## 결정 2: 근사는 근사라고 말한다

기존 `overflow` 는 `문자 수 × 확장률` 이다. 폰트 메트릭이 없을 때 쓸 수 있는 유일한 신호이므로
**없애지 않는다.** 대신 폰트 메트릭(`avgCharWidth`)이 주어지면 그것으로 계산하고,
주어지지 않으면 위반에 `approx: true` 를 붙인다.

조용한 근사가 근사 없는 것보다 나쁜 이유는 **틀린 확신**을 주기 때문이다.
이것은 내가 3차 사이클에서 만든 결함이다.

`Ruling: 근사 판정은 결과에 근사임을 표시한다 — 조용한 근사는 틀린 확신을 만든다.`

## 결정 3: 유저 생성 텍스트가 있으면 서브셋을 금지한다

서브셋은 폰트 용량 문제의 표준 해법이다. 그런데 닉네임·채팅처럼 **어떤 글자가 올지 모르는**
텍스트가 있으면 서브셋한 폰트에서 유저 이름이 두부가 된다.
로블록스에서 실제로 터지는 문제이고, 용량 최적화의 대가가 유저 이름 깨짐이면 최적화가 아니다.

그래서 `userGeneratedText: true` 인데 `subset: true` 인 폰트는 위반이다.

## 결정 4: 글리프 커버리지는 로케일이 요구하는 스크립트로 판정한다

폰트마다 글리프 목록을 전부 들고 비교하는 것은 이 층에서 할 일이 아니다(파일 파싱이 필요하다).
대신 **폰트가 선언한 `scripts` 와 로케일이 요구하는 `script` 를 대조한다.**
선언 대조는 실제 파일 검사보다 약하지만, 지금 0 인 것을 선언 수준으로 올리는 것이 먼저다.
실제 파일 파싱은 필요해지면 그때 얹는다 — 선언이 있어야 얹을 자리가 생긴다.

## 파일 배치

