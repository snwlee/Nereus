# 설계 — 세션별 handoff

## D1. 세션 식별자는 훅이 알려준다 (설계의 축)

모델은 자기 `session_id` 를 모르고, 스킬이 부르는 Bash 에도 그 값이 오지 않는다.
`session_id` 를 받는 곳은 훅뿐이다. 그래서 **SessionStart 훅이 이 세션의 handoff 경로를
문자열로 주입**하고, handoff·finish 스킬은 그 경로에만 쓴다. 대안(스킬이 경로를 스스로 계산)은
세션을 구분할 입력이 없어 성립하지 않는다.

## D2. 최신 판정은 mtime, 파일명은 사람을 위한 것

파일명의 시각은 **세션 시작 시각**이라 쓰기 시각과 다르다. 09:00 에 시작한 세션이 14:30 에 쓰면
14:00 에 시작한 세션보다 이름이 앞선다. 그래서 "최신"은 **mtime 으로 판정**하고, 동률이면 이름 내림차순으로 깬다.
파일명의 시각은 사람이 목록을 훑을 때를 위한 것이다.

## D3. compact 는 같은 세션이므로 같은 파일을 재사용한다

`source=compact` 는 같은 대화다. 디렉터리에서 같은 `sid8` 을 가진 파일이 있으면 새로 만들지 않고 그것을 쓴다.
안 그러면 한 세션이 컴팩션마다 파일을 하나씩 남긴다.

## D4. 경로 결정은 순수 함수, fs 는 주입

`sessionHandoffPath` 는 디렉터리 목록(`entries`)과 `now` 를 인자로 받는다.
훅 통합 없이 테스트한다. 경로 계산은 지금처럼 `paths.mjs` 밖으로 나가지 않는다.

## D5. 루프 서브세션은 경고 대상이 아니다

reset 루프는 반복마다 새 세션이다. 30분 창 안에 자기 직전 반복들이 그대로 들어와 매번 경고가 뜬다.
러너가 `NEREUS_LOOP=1` 을 스폰 환경에 넣고, 훅은 그 값이 있으면 경고를 생략한다.
읽기·쓰기 규칙 자체는 바꾸지 않는다 — 반복은 직전 반복의 파일을 최신으로 읽는다(원하는 동작이다).

## D6. wave 회수는 복사만, 메인 handoff 는 모델이 쓴다

러너가 메인 handoff 를 직접 편집하면 "전체 재작성은 모델이 한다"는 원칙이 깨지고,
기계가 쓴 단락과 모델이 쓴 단락이 섞인다. 러너는 워크트리의 최신 handoff 를
`.nereus/waves/<wave 이름>.md` 로 **복사**만 하고, 프롬프트가 다음 반복에게
"흡수하고 그 파일을 지워라"고 시킨다.

## D7. 보존 정책

최근 10개 유지, mtime 이 30일보다 오래된 것 삭제. 훅이 주입 뒤 조용히 수행하고 실패는 삼킨다
(정리 실패로 세션 시작을 막지 않는다).
