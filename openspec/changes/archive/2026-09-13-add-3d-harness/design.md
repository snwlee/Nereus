# design — add-3d-harness

## 1. 열린 질문 둘의 확정

### Q1. 예산 기준값을 어디서 받나 → **입력으로 받는다. 없으면 판정하지 않는다**

드로우콜 상한·텍스처 예산은 **정책 수치가 아니라 프로젝트 운영값**이다.
기기 등급·해상도·씬 복잡도가 정한다. 플러그인 데이터에 박으면 정책인 척하면서 낡는다
(`nereus-ads` 의 쿨다운·세션 상한과 같은 판단).

기준이 없으면 **지어내지 않는다.** `unmeasured` 에 남기고 무엇이 없어서 판정 못 했는지 적는다.
`Ruling: 기준이 없으면 판정하지 않고, 판정하지 않았다고 적는다.`

**단, 데이터로 두는 것이 하나 있다 — 텍스처 슬롯 목록이다.**
`map`·`normalMap`·`roughnessMap`·`metalnessMap`·`aoMap`·`emissiveMap`… 은
**three.js 가 정하는 값**이지 우리가 정하는 값이 아니다. 출처 URL·확인일과 함께 둔다.
`Ruling: 남이 정하고 남이 바꾸는 값은 데이터로 두고 출처를 붙인다.`

### Q2. 정적 검사와 런타임 증거를 나눌 것인가 → **나눈다. 경계는 "앱이 돌아야 하는가"**

둘 다 게이트라 `nereus-l10n` 의 게이트/조언자 축과는 다르다. 나누는 축은 **실행 전제**다.

| | `scene-scan.mjs` | `render-budget.mjs` |
|---|---|---|
| 입력 | 소스 텍스트 | `renderer.info` 증거 |
| 앱이 돌아야 하나 | **아니오** | **예** |
| CI 에서 | 항상 돈다 | 증거가 있을 때만 |

합치면 **소스만 있으면 잡을 수 있는 것까지 "증거가 없다"로 건너뛰게 된다.**
도너가 정확히 그 상태다 — `renderer.info` 0건이라 런타임 증거가 아예 없는데,
dispose 결함은 소스만으로 잡힌다. 합쳤으면 **못 잡았다.**

## 2. `incomplete-dispose` 를 어떻게 정적으로 판정하나

이 검사기의 핵심이고, 가장 틀리기 쉬운 부분이다.

### 판정 규칙

머티리얼에 `.dispose()` 를 부르는 함수 본문을 본다.

1. 본문이 **속성 순회**를 하면(`isTexture` 를 참조) → **완전.** 슬롯 이름을 세지 않는다.
   새 슬롯이 three.js 에 추가돼도 자동으로 덮이기 때문이다. 이게 `game_view.html` 의 방식이다.
2. 순회가 없으면 **명시적으로 언급한 슬롯을 센다.** 데이터의 슬롯 목록 대비 빠진 것을 보고한다.
   이게 `difference_engine.js` 의 방식이고 `.map` 하나뿐이다.

### 왜 "슬롯을 전부 나열했으면 통과"가 아니라 순회를 우대하나

나열은 **three.js 가 슬롯을 추가하는 순간 조용히 불완전해진다.**
순회는 안 그렇다. 통과시키되 **같은 등급으로 보지 않는다** — 나열 방식은 통과해도
`unmeasured` 에 "슬롯 목록 확인일 기준"이라고 남긴다. 우리 목록이 낡으면 판정도 낡는다.

### 놓치는 것을 명시한다

정규식 기반이고 **AST 파서가 아니다.** 새 런타임 의존성을 추가하지 않는다는 제약 때문이다.
따라서 못 잡는 것:
- 다른 파일의 헬퍼를 import 해 부르는 경우(본문이 이 파일에 없다)
- 동적으로 만들어지는 슬롯 이름
- 주석 처리된 코드를 실제 코드로 오인

**이것들을 `unmeasured` 에 싣는다.** `Ruling: 답할 수 없는 것을 결과에 싣는다 —
검사기가 다 본다고 믿게 만드는 것이 더 나쁘다.`

## 3. 누수는 단발 스냅샷으로 판정하지 않는다

`renderer.info.memory.geometries` 가 크다는 것은 **누수가 아니다.** 큰 씬일 수 있다.
누수는 **같은 상태로 돌아왔는데 수가 늘어난 것**이다.

```json
"samples": [
  { "label": "scene-1 진입", "info": { "memory": { "geometries": 120, "textures": 8 } } },
  { "label": "scene-2 갔다가 scene-1 복귀", "info": { "memory": { "geometries": 240, "textures": 16 } } }
]
```

같은 `label` 로 두 번 이상 들어온 표본만 비교한다. 표본이 하나뿐이면 **누수를 판정하지 않고**
`unmeasured` 에 싣는다. 단발로 "많다"고 하면 정상 씬이 전부 빨개지고,
**전부 빨개지는 게이트는 꺼진다**(ToonTone 461:0).

예산 초과(`budget-exceeded`)는 단발로도 판정된다 — 기준이 주어졌을 때만.

## 4. 라우트를 좁힌다 — 플러그인이 다섯이 된다

`MAX_HITS=2` 인데 후보가 다섯이다. **`3D`·`씬`·`렌더` 단독 단어는 쓰지 않는다.**

| 스킬 | 잡는 것 |
|---|---|
| `threejs` | `three.js` · `threejs` · `webgl` · `webgpu` · `glTF` · `OrbitControls` |
| `renderbudget` | `드로우콜` · `draw call` · `renderer.info` · `GPU 메모리` · `프레임 드랍` · `dispose` |

**스킬을 둘로 한다.** 세 번째를 만들 근거가 아직 없다 — 검사기가 둘이고 도메인이 하나다.
`Ruling: 라우트 없는 스킬은 존재하지만 도달할 수 없다` 의 역도 참이다 —
검사기 없는 스킬은 문서일 뿐이고, 우리는 문서를 만들지 않기로 했다.

이름은 `nereus-game:asset`(에셋 생성)·`nereus:frontend`(웹 UI)와 겹치지 않는다.
에이전트는 `graphics-engineer` — 기존 다섯 플러그인 18개와 겹치지 않는다.

## 5. 경계 — `nereus-game:asset` 과 무엇이 다른가

| | `nereus-game:asset` | `nereus-3d` |
|---|---|---|
| 언제 | 에셋을 **만들 때** | 에셋이 **돌아갈 때** |
| 무엇 | TRELLIS·Blender 경유·폴리곤 예산 | dispose·드로우콜·GPU 메모리 |
| 전제 | Blender 가 PATH 에 | 없음 |

둘 다 "폴리곤 수"를 말하지만 **`asset` 은 반입 전 파일**을, **`3d` 는 런타임 렌더**를 본다.
`asset` 의 폴리곤 예산을 통과한 모델도 122개를 한 화면에 놓으면 드로우콜에서 죽는다.
**같은 수치를 두 곳에서 정하지 않는다** — `asset` 은 파일, `3d` 는 프레임이다.
