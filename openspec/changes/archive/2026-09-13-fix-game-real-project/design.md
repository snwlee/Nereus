# design — fix-game-real-project

## 결정 1: 형식을 넓히지 말고 **셌는지 여부를 낸다**

`countScope` 에 spec-kit 정규식을 하나 더 얹는 것만으로는 다음 형식에서 또 0 이 된다.
근본 문제는 정규식이 좁은 것이 아니라 **"0개"와 "못 셌다"가 구분되지 않는 것**이다.

태스크가 정말 0개인 tasks.md 와, 형식을 못 알아봐서 0 인 tasks.md 는 전혀 다른 상태인데
호출자에게 똑같이 `{tasks: 0}` 으로 도착한다. 그래서 반환에 `matched` 를 싣는다 —
어떤 형식으로 셌는지, 못 셌으면 못 셌다고.

`Ruling: 미설정과 실패를 구분한다` 의 같은 적용이다.

기존 반환 키(`tasks`·`flows`)는 **그대로 둔다.** 새 키만 더한다 —
`MUST NOT: 기존 export 의 반환 형태를 바꾸지 않는다`.

## 결정 2: 체크박스 총수를 하한으로 쓴다

형식을 못 알아봤을 때 "모르겠다"로 끝내면 `recommendTrack` 이 쓸 값이 없다.
`- [ ]` / `- [x]` 총수는 **어떤 형식이든** 셀 수 있고, 태스크 수의 **상한**이다
(Steps 체크박스가 섞이므로). 이것을 `checkboxes` 로 같이 낸다.

`recommendTrack` 은 `matched === null` 일 때 임계 비교를 **하지 않는다.**
상한으로 게이트를 돌리면 몇 배로 부푼 수로 판정하게 된다 —
`countScope` 주석이 애초에 경고한 그 실수다. 대신 `reasons` 에
`scope-unknown` 을 싣고 추천은 강제 조건만으로 낸다.

## 결정 3: l10n 제외는 **삭제가 아니라 분류**다

생성물과 개발자 메시지를 그냥 빼면, 빼먹은 것과 검사 통과한 것이 구분되지 않는다.
`scanL10n` 은 `violations` 외에 `skipped: [{ reason, count }]` 를 낸다.

| 분류 | 근거 | 왜 사용자 노출이 아닌가 |
|---|---|---|
| `generated` | 경로가 `generated/`·`.g.dart`·`.freezed.dart`·`l10n/generated/` | 도구 산출물이다. 고칠 대상은 소스 표다 |
| `dev-message` | 같은 줄에 `throw`·`assert`·`Exception`·`Error(`·로그 호출 | 플레이어에게 도달하지 않는다 |

**둘 다 줄 단위 판정이다.** 파일 전체를 지우지 않는다 — 생성물이 아닌 파일에도
개발자 메시지는 섞여 있고, 그 파일의 사용자 문자열은 계속 검사되어야 한다.

## 결정 4: 제외 규칙은 데이터다

경로 패턴과 개발자 메시지 토큰은 **언어·프레임워크마다 다르다**(`.g.dart` 는 Dart,
`.generated.cs` 는 Unity, `__pycache__` 는 Python). 코드에 박으면 스택이 늘 때마다
lib 을 고치게 된다 — `Ruling: 확장은 코드가 아니라 데이터로 받는다`.

호출자가 `exclude: { generated: [...], devMessage: [...] }` 로 덮어쓸 수 있게 하고,
기본값은 lib 안에 둔다. 기본값이 없으면 호출자가 매번 전부 선언해야 해서 아무도 안 쓴다.

## 결정 5: 픽스처를 실제 산출물에서 뜬다

이 세 결함이 전부 초록 단위 테스트를 통과했다. 픽스처를 **하네스 자신의 출력 형식**으로
썼기 때문이다. 그래서 이번 테스트는 실제 프로젝트에서 뜬 조각을 픽스처로 쓴다:

- spec-kit `tasks.md` 의 실제 줄 (`- [x] T001 Flutter 프로젝트를 ...`)
- Flutter l10n 생성 파일의 실제 줄 (`String get hintGranted => 'Hint received';`)
- Dart 예외 메시지의 실제 줄 (`throw ContentPackFormatException('최상위가 객체여야 한다');`)

**ToonTone 을 읽는 테스트는 쓰지 않는다.** 다른 저장소라 CI 에서 없을 수 있고,
없으면 조용히 건너뛰는 테스트가 된다 — 그게 바로 이 사이클이 고치는 양상이다.
줄을 **리터럴로 박는다.**

`Ruling(신규): 검사기 픽스처는 하네스 출력이 아니라 실제 프로젝트 산출물에서 뜬다.`

## 측정 결과 (고친 뒤)

| 검사기 | 전 | 후 |
|---|---|---|
| `countScope` (ToonTone tasks.md) | 0개 · 추천 `many` 근거 0건 | **188개** · `matched: "spec-kit"` · 추천 `deep` |
| `scanL10n` (ToonTone lib/**/*.dart) | 461건 · 진짜 0건 | **69건** (skipped: generated 315 · dev-message 76) |

188 은 `grep -cE '^- \[[ x]\] T[0-9]+ '` 실측과 정확히 일치한다.

69건 안에서 **ToonTone 의 실제 버그 1건**을 찾았다:
`lib/shared/leaderboard/leaderboard_period.dart:18` 의 `label` 이 `\'오늘\'` · `\'이번 주\'` ·
`\'전체\'` 를 하드코딩해 리턴하고 `leaderboard_page.dart:169` 가 그대로 렌더한다.
**영어 로케일 사용자에게 리더보드 탭이 한국어로 나온다.** 하네스를 실제 게임에 붙인
첫 시도에서 나온 첫 진짜 소득이다. (ToonTone 저장소 수정은 이 사이클 범위 밖이다 — 별도로 다룬다.)

## 남은 한계 (알고 남긴다)

- 문자열 보간 식별자가 사용자 문장으로 오인된다(`\'$collectedCards / $totalCards\'`).
  69건의 상당수가 이 부류다. `USER_FACING` 이 "두 글자 이상 단어 + 공백"을 보기 때문이다.
  보간 안을 지우고 판정하면 줄어들지만, 그러면 보간 **사이**의 진짜 문장도 같이 지워진다.
  실측 표본이 더 필요해 이번 사이클에서 건드리지 않는다.
- 개발자 메시지 문맥은 괄호 균형 **근사**다. 문자열 안의 괄호도 세므로 틀릴 수 있다.
  파서를 넣을 만한 근거가 아직 없다.
