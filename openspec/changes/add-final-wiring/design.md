# design — add-final-wiring

## 결정 1: OCR 은 도구 문제가 아니라 호출 문제였다

세 사이클 동안 `.nereus/review.md` 와 handoff MUST NOT 에 "OCR 은 커밋된 diff 를 못 본다"고 적었다.
이번에 `--help` 를 읽고 실측해 보니 `--from`/`--to` 가 있고 잘 동작한다.

오해가 굳은 경위:
1. 인자 없이 `ocr delegate preview` 를 불렀다 → workspace(미커밋) 모드로 떨어진다
2. 그 시점 미커밋 파일이 전부 `.md` 였다 → `unsupported_ext` 로 제외되어 `0 reviewable`
3. "0 reviewable" 을 도구 한계로 읽었다

**교훈은 도구를 불가로 기록하기 전에 `--help` 를 읽는다는 것이다.** MUST NOT 에 남긴 판단도
근거가 얇으면 재검증해야 한다. 이번 사이클에서 그 항목을 지운다.

## 결정 2: 미설정은 실패가 아니다

2단 게이트는 API 키가 필요하다. 키가 없을 때 게이트를 막으면 **키 없는 모든 세션에서 finish 가
불가능해진다** — 하네스 자체를 고칠 수도 없게 된다. 로블록스 훅에서 이미 같은 판단을 했다
(도구 부재는 훅 실패가 아니다).

구분은 셋이다: `skipped`(대상 아님) · `unconfigured`(전제 없음, 통과) · `failed`(실제 실패, 차단).
셋을 섞으면 게이트가 거짓말을 한다.

## 결정 3: 지배 전략은 세 번째 축이다

프로파일 실패 양상이 지금 둘이다 — `bottleneck`(타이쿤) · `cliff`(오비).
PvP 는 다르다. 자원이 충분하고 난이도 곡선이 매끄러워도 **선택지 하나가 나머지를 압도하면** 게임이 죽는다.

`economy.options`(이름 + 비용 + 효과)를 받아 효율 = 효과/비용 을 계산하고,
최고 효율이 중앙값의 `balance.dominanceRatio` 배를 넘으면 지배 전략으로 보고한다.
선택지 정보가 없으면 빈 배열이다 — 이 축을 쓰지 않는 장르가 있기 때문이다.

## 결정 4: 에셋 doctor 는 판정만 한다

이 맥에서는 생성 모델을 돌릴 수 없고 Windows 머신은 이 세션의 대상이 아니다.
그러나 **"무엇이 없어서 어느 단계가 막히는가"는 지금 판정할 수 있고**, 그것이 실제로 필요한 정보다.
설치를 시도하지 않는다. 판정하고 알린다.
