# design — add-game-liveops

## 결정 1: 사운드는 생성이 아니라 설계다

`asset` 이 이미 오디오 생성을 덮는다(ElevenLabs 호스티드, TTS, BGM). 그래서 `sound` 는
**생성된 소리를 어떻게 배치·예산·검증할 것인가**만 본다. 두 스킬을 합치지 않는 이유:

- `asset` 은 "반입 직전까지"가 범위다. 사운드 설계는 반입 **이후**의 문제다.
- 합치면 `asset` 이 2D·3D·오디오 생성 + 오디오 설계까지 네 가지를 들고 비대해진다.

`Ruling: 사운드 도메인은 asset 의 하류다 — 생성은 asset, 배치·예산·검증은 sound.`

## 결정 2: 라이브옵스는 지표 없이도 게이트가 성립한다

실제 운영 지표(로블록스 Open Cloud Analytics)는 아직 없다. 그런데 **계획의 내적 정합성**은
지표와 무관하게 판정할 수 있다:

| 검사 | 지표 필요 | 판정 방법 |
|---|---|---|
| 이벤트 캘린더 겹침 | 아니오 | 구간 겹침 계산 |
| 경제 싱크/소스 균형 | 아니오 | 선언된 소스 합 vs 싱크 합의 비율 |
| 리텐션 곡선 가정 | 아니오 | 단조 감소·D1≥D7 같은 형태 제약 |
| 롤백 경로 존재 | 아니오 | 각 이벤트에 rollback 선언 유무 |
| 실측 리텐션 대비 편차 | **예** | `metrics` 주입구가 있을 때만 추가 판정 |

지표는 **선택 인자**로 받는다. 없으면 그 항목만 `unmeasured` 로 보고하고 나머지는 그대로 판정한다.

`Ruling: 라이브옵스 게이트는 지표 부재로 꺼지지 않는다 — 계획 정합성과 실측 검증을 분리한다.`
(기존 `Ruling: 미설정과 실패를 구분한다` 의 도메인 적용이다.)

## 결정 3: 언어 집합은 코어가 아니라 데이터다

`locales.json` 한 장. 언어 추가가 파일 한 줄이 되게 한다. 장르 프로파일과 같은 이유다 —
검사기 안에 언어 목록을 박으면 시장이 바뀔 때마다 검사기를 고쳐야 한다.

**알 수 없는 로케일은 기본값으로 떨어지지 않고 던진다.** `loadProfile` 과 같은 규율이다.

## 결정 4: 확장률은 언어별 상수로 둔다

UI 폭 위험은 "번역하면 문자열이 얼마나 길어지는가"로 판정한다. 실제 번역 없이도
언어별 평균 확장률(예: DE 약 1.35, PT-BR 약 1.3, JA/ZH 약 0.6)을 상수로 두면
`maxWidth` 를 넘길 문자열을 **지금** 찾아낼 수 있다.

이 상수는 추정이다. 그래서 `locales.json` 에 값으로 두고 출처를 주석으로 남긴다 —
코드에 박아 두면 나중에 실측으로 고칠 때 어디를 고쳐야 하는지 모른다.

## 결정 5: 프로파일 확장은 선택 키다

`validateProfile` 의 `REQUIRED` 를 늘리지 않는다. 늘리면 기존 프로파일 4종이 전부 무효가 되고,
`Ruling: 기존 export 의 반환 형태를 바꾸지 않는다` 를 어긴다.
`sound` · `liveops` · `l10n` 은 **없으면 그 도메인 검사가 "프로파일에 기준이 없다"고 보고**한다 —
조용히 기본값으로 판정하지 않는다.
